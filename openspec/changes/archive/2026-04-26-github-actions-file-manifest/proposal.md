# Proposal: GitHub Actions File Manifest

## Intent

Replace the runtime GitHub Contents API call in `index.html` with a locally-served
`files.json` manifest generated by a GitHub Action on every push. This eliminates
the 60 req/hour unauthenticated API rate limit, makes the homepage work offline
(cached), and enables proper display of files organized by user directory.

## Problem

The current `index.html` calls `api.github.com` client-side to list teleprompter
files. It is rate-limited, requires internet access on every load, and only scans
the root directory — the user subdirectories (`/Amélie/`, `/AnneSophie/`, etc.)
are invisible.

## Scope

- A GitHub Action (`.github/workflows/generate-manifest.yml`) that runs on every
  push to `main`, scans all user subdirectories, and writes `files.json` to the
  repo root.
- `files.json` structure: a dictionary keyed by user directory name, each value
  an array of HTML filenames.
- Update `index.html` to `fetch('./files.json')` instead of the GitHub API, and
  render the list grouped by user.
- The Action commits `files.json` back to `main` if it changed.

## Out of Scope

- Changing the generator or any teleprompter logic.
- Authentication or private repo support.
- Pagination (the file count per user is small).

## Approach

The Action uses a simple shell or Node.js script to walk the known user
directories, collect `.html` filenames (excluding `index.html` and
`generator.html`), and write the JSON. No external dependencies needed.

`index.html` rendering changes from a flat list to a grouped layout:
one section heading per user, links beneath it — mirroring the actual
directory structure.
